# MVP 实施路线

## 原则

先验证内容能否帮助用户和带来咨询，再扩大自动化。不要先开发复杂后台，也不要先接自动发布。

## 阶段 0：底层规则

交付物：

- 账号定位。
- 人物事实与观点库。
- 产品知识库。
- 内容质量和真实性规则。
- 平台内容标准。
- 数据结构和提示词。

验收：

- AI 不再编造第一人称。
- 产品权益不会被自动补全。
- 同一选题能生成明显不同的平台版本。

## 阶段 1：人工验证内容模型

任务：

- 收集至少一批真实用户问题。
- 生成 20 个候选选题并评分。
- 选择 5 个不同类型母题。
- 每个母题完成研究包、母稿和多平台版本。
- 由本人审核并实际发布。

验收重点：

- 用户是否看懂并完成。
- 评论是否出现真实问题。
- 收藏、关注和咨询是否来自目标用户。
- 哪些栏目更适合流量，哪些更适合转化。

## 阶段 2：半自动生产

优先自动化：

- 素材标准化。
- 去重和问题聚类。
- 选题评分。
- 研究包初稿。
- 多平台改写。
- 图片模板渲染。
- 质检报告和发布包整理。

仍保留：

- 实验是否真实完成的确认。
- 第一人称和产品事实确认。
- 最终发布。

## 阶段 3：反馈闭环

- 自动回收平台数据。
- 按用户问题、栏目、标题、封面和 CTA 复盘。
- 区分流量内容和获客内容。
- 更新选题评分权重。
- 把人工修改记录转成新的表达规则。

## 阶段 4：规模化

只有前面稳定后再考虑：

- 更高频生产。
- 多账号或多语言版本。
- 更复杂实验系统。
- 官方允许范围内的草稿箱或发布接口。
- 自动预算与模型路由。

## 不建议的开发顺序

错误顺序：

```text
爬虫 → 十几个 Agent → 自动发文 → 再考虑内容质量
```

推荐顺序：

```text
事实和规则 → 真实问题 → 选题验证 → 内容验证 → 质检 → 自动化 → 数据闭环
```
