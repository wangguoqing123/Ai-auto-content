# AI 不掉队俱乐部产品知识库

## 1. 产品不是简单教程群

AI 不掉队俱乐部不能简化成“AI 教程 + 交流群”。课程、案例、资料和社群交流都服务于同一个目标：让已经接触 AI、但还没有稳定用起来的人，通过真实任务和持续实践，把 AI 接入自己的内容、工作和真实业务。

本文件用于人类阅读和解释。`config/product.yaml` 是选题、写作、CTA 和产品审核唯一的机器可读产品事实源；生成内容时不能从本文件或 Prompt 自行补全配置中没有的权益。

## 2. 产品定位

> AI 不掉队俱乐部，是一个面向已经开始接触 AI、但还没有稳定用起来的人，以学习路径、基础课程、工具实操、完整项目、真实案例和社群交流，帮助用户把 AI 逐步接入内容、工作和真实业务的长期实践学习社群。

核心品牌主张：

> 不是追每一个新工具，而是把 AI 真正用起来。

最终目标：

> 把 AI 稳定接入自己的内容、工作和真实业务。

## 3. 用户加入前与加入后的变化

| 加入前 | 希望逐步达到的状态 |
|---|---|
| 收藏很多 AI 工具和教程 | 能按真实结果选择工具 |
| 会基础对话，但输出不稳定 | 能稳定完成日常任务 |
| 会单个工具，却不会完成完整任务 | 能拆解复杂任务 |
| 每次使用都从零开始 | 能把多个工具组成工作流 |
| 不知道先学什么、后学什么 | 能把跑通的方法沉淀成 Skill、模板或可复用流程 |
| 一个人摸索，遇到问题不知道怎样继续 | 能把 AI 接入内容、工作和真实业务 |

这是学习方向，不是保证学会、保证就业、保证收入或保证业务结果。

## 4. 四个产品机制

### 4.1 会员知识库

- 提供工具、方法、教程和案例。
- 可以表达“持续更新”。
- 不能自动补充每周新增数量、具体更新频率或固定更新时间。

### 4.2 清晰学习路径

- 第一次进入时，先选择未来 2～4 周最想完成的一个结果。
- 一次只走一条学习路径。
- 不是先把所有工具学一遍。

### 4.3 真实项目拆解

- 强调真实任务、真实过程和可复用实践。
- 可以展示失败点和调整过程。
- “跑通过”“真实项目”“能够复用”“实测有效”必须绑定具体项目或实验记录。

### 4.4 社群交流同行

- 可以在群内提问和交流。
- 遇到问题可以带到社群讨论。
- 当前不能承诺固定回复时间、固定答疑场次或即时响应 SLA。

## 5. 三条学习原则

1. **实践优先，用结果判断工具。** 不追最新模型和最长工具清单，以真实任务结果判断工具是否值得使用。
2. **遇事不决，先问 AI。** 先把目标、背景和资料交给 AI，帮助梳理、尝试和排查；AI 解决不了，再带具体问题进入社群交流。
3. **真实实践，值得被分享。** 分享什么有效、哪里卡住、哪些地方失败、最后怎样调整；真实过程比漂亮结果更有价值。

第一次使用规则：

> 先选择未来 2～4 周最想完成的一个成果，一次只走一条路径。

## 6. 共同基础与实战分流

产品结构是“共同基础 + 实战方向”，不是六门彼此无关、平均交付的课程。

共同基础包括：

- **AI 基础认知**：模型、工具、智能体、工作流、工具选择与能力边界。
- **稳定使用 AI**：提示词基本结构、上下文、参考资料、任务拆解、检查和迭代。
- **智能体与工作流**：知识库、Skill、MCP、多工具协同和可重复运行流程。

实战方向包括：

- AI 内容创作。
- AI 视频生产。
- AI 小工具与工作提效。

实战方向只表示产品结构方向。是否已经完整交付，必须继续读取交付状态，不能由方向名称推断。

## 8. 交付成熟度边界

| 状态 | 含义 | 产品适配分上限 |
|---|---|---:|
| `confirmed_delivered` | 截图和目录已确认具体交付 | 10 |
| `confirmed_partial` | 已确认部分内容，不能声称覆盖整个方向 | 7 |
| `confirmed_container` | 容器存在，本轮证据未展示全部内容 | 5 |
| `direction_confirmed_delivery_unverified` | 海报确认方向，目录证据不足 | 3 |
| `unknown` | 证据不足 | 0 |

海报描述的是产品方向；会员目录截图证明的是当前可见交付。二者不能互相替代。AI 视频当前只能按方向处理，不能使用 `club` CTA，也不能得到满额产品适配分。

## 9. 定价规则

- 当前用户确认价格：365 元/年，确认日期为 2026-08-14。
- 海报标准价格：499 元/年。
- 海报规则：前 200 名为 365 元/年，第 201 名起为 499 元/年。
- 当前会员序号和剩余名额未知。
- 不能自动声称“只剩多少名额”“马上涨价”“最后一天”或“即将恢复 499”。
- 任何正式销售内容生成前，必须重新读取 `config/product.yaml` 的 `pricing.current_offer`。
- 价格变化只修改 `config/product.yaml`，不能把价格复制进 Prompt 或 `config/project.yaml`。

## 10. 适合与不适合人群

适合：已经开始接触 AI，但还没有稳定用起来；希望完成真实任务、建立工作流；愿意亲手实践和检查结果；希望遇到具体问题时进入社群交流的人。

不适合：期待购买后自动获得收入或业务结果；要求一对一代做、即时响应或固定服务 SLA；不愿实践，只想收藏更多工具；主要需要模型训练和算法研究的人。

## 11. 免费内容与付费产品边界

免费内容必须完整解决一个具体小问题，给出可执行步骤、判断标准或可验证结果，不能故意省略关键步骤逼迫付费。

付费产品承接的是更系统的学习路径、共同基础、已确认的工具实操、更多真实实践以及社群交流。CTA 不是每篇必有：产品关系弱时使用 `none`；已交付模块可使用 `light`；只有 `confirmed_delivered` 或 `confirmed_partial` 直接承接，且免费内容已经完整交付一个小结果时，才允许 `club`。

## 12. 已确认表达

稳定 claim ID 由 `config/product.yaml` 管理，包括产品名称、主理人、品牌线、产品定位、当前价格、标准价格、长期实践社群形态、四个机制、共同基础、已确认的内容自动化与 Codex 课程、案例库的已确认部分、模板与更新容器、目标人群和品牌主张。

“持续更新”作为泛化表达可以使用，但不得自动加上频率、数量或固定日期。

## 13. 需证据表达

以下说法必须带项目记录、实验结果或用户案例证据：

- 已真实跑通。
- 能够复用。
- 真实项目。
- 有实测结果。
- 用户案例。
- 效率提升。

没有 evidence reference 时，Claim API 必须拒绝这些表达。

## 14. 禁止自动承诺

系统不得自动生成会员人数、教程数量、固定更新频率、固定答疑频率、即时响应、一对一支持、作业批改、直播课、模板数量、保证学会、保证收入、保证就业、保证业务结果、退款政策、续费政策、用户成功率、剩余名额或涨价倒计时。

未知 claim ID 默认拒绝；未知字段不能被转成“已确认”。

## 15. 产品信息更新流程

1. 取得新的用户明确确认、当前产品材料或交付目录证据，并记录事实优先级。
2. 只在 `config/product.yaml` 更新产品事实、价格、交付状态、claim 或未知字段。
3. 如学习阶段、pillar、适配上限或 CTA 策略变化，再更新 `config/content-fit.yaml`。
4. 运行 `npm run product:check`，确保引用、claim、比例、状态上限全部有效。
5. 运行 `npm run schema:generate` 和 `npm run schema:check`，提交同步的 JSON Schema。
6. 更新本文件和 `docs/20-product-truth-and-content-fit.md` 的人类说明，并运行完整测试。

没有新证据时，未来 Agent 只能保留现状或标记未知，不能把海报方向、容器名称、旧文档或常识推断成新权益。
