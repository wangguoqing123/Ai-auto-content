# 系统架构

## 1. 架构原则

- 固定流程优先于大量 Agent 自主讨论。
- 每一步都有清晰输入、输出和状态。
- 事实和证据链贯穿全流程。
- 内容母题与平台版本分离。
- 低成本任务和高推理任务使用不同模型。
- 人只保留少量高价值判断，不承担重复劳动。

## 2. 推荐技术组合

第一版建议：

- 飞书多维表格：内容运营和人工查看中心。
- n8n：流程编排。
- 大模型：分类、研究、写作、审核和改写。
- 网页搜索与解析：公开素材收集。
- Playwright：页面截图和必要的真实操作验证。
- HTML/SVG/Canvas：封面、卡片和信息图渲染。
- 对象存储：图片、截图、实验文件和发布资产。
- 飞书机器人：推送待发布卡片和异常提醒。

这只是推荐方案，最终技术选型需结合现有账号、成本和部署条件确认。

## 3. 核心模块

### 素材采集器

输入：官方资料、用户问题、社群记录、评论、公开讨论、历史内容。

输出：标准化素材卡和证据卡。

### 去重与聚类器

- 语义去重。
- 相同用户问题聚类。
- 识别历史已写内容。
- 记录新信息和新增价值。

### 选题规划器

- 根据用户痛点、行动性、展示性、证据、传播性和产品匹配评分。
- 低于阈值或触发硬性淘汰的选题不进入生产。

### 研究与实验模块

- 整理事实、来源和争议。
- 设计必要实验。
- 保存输入、输出、模型、提示词、耗时、成本、截图和结论。

### 母稿编辑器

先生成与平台无关的内容母稿，确保逻辑、价值和事实完整。

### 平台适配器

分别生成公众号、小红书和 X 原生版本，不做机械压缩。

### 视觉生成器

优先使用真实截图、流程图和模板渲染，概念图仅作为补充。

### 质量审核器

依次检查：

- 事实。
- 第一人称。
- 产品权益。
- 小白可理解性。
- 原创性。
- 表达质量。
- 平台合规。

### 发布包生成器

把标题、正文、图片、标签、CTA、来源和质检报告整理成一个可上传文件夹或飞书卡片。

### 数据回收器

记录曝光、阅读、收藏、评论、关注、私信、资料领取、合格咨询和付费结果。

## 4. 状态机

```text
INBOX
→ NORMALIZED
→ SCORED
→ APPROVED_TOPIC
→ RESEARCHING
→ NEEDS_EXPERIMENT
→ DRAFTING
→ REVIEWING
→ VISUALIZING
→ READY_FOR_HUMAN
→ PUBLISHED
→ REVIEWED_PERFORMANCE
→ ARCHIVED
```

退回状态：

```text
REJECTED_LOW_VALUE
REJECTED_NO_EVIDENCE
REJECTED_DUPLICATE
BLOCKED_POLICY
NEEDS_FACT_CONFIRMATION
```

## 5. 模型分工

- 去重、标签、格式转换：低成本模型。
- 选题判断、研究和母稿：强推理模型。
- 事实审核和反方审稿：与写作模型不同的强模型交叉检查。
- 图片理解：视觉模型。
- 概念图：图片生成模型。
- 文字排版：程序模板，不交给图片模型。

## 6. 日志与可追溯性

每次模型调用至少保存：

- 工作流版本。
- 提示词版本。
- 模型和参数。
- 输入记录 ID。
- 输出记录 ID。
- 运行时间和成本。
- 错误信息。
- 人工修改记录。

## 7. 人工检查点

第一版保留一个最终检查点，确认：

- 标题不过度承诺。
- 没有虚假第一人称。
- 观点本人认可。
- 产品承接和发布动作合适。

后续可以按风险等级减少检查，但不默认完全取消最终责任。

## 8. 安全与隐私

- 密钥只放环境变量或密钥管理工具。
- 公开仓库不提交客户聊天、社群原始记录和个人信息。
- 所有用户素材先脱敏，再进入研究或内容流程。
- 截图自动检测手机号、微信号、邮箱、姓名和头像等敏感信息。
- 生成内容保留来源和许可状态。
