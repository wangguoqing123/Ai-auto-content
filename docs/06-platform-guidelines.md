# 多平台内容与配图标准

> 平台功能和规则会变化。本文件定义项目内部的内容标准，不替代发布时对最新平台规则的核验。

## 1. 微信公众号

### 目标

- 建立深度信任。
- 完整解释一个方法或案例。
- 承接长期阅读、搜索和产品转化。

### 推荐结构

```text
用户为什么遇到这个问题
→ 常见错误做法
→ 先给核心结论
→ 完整操作步骤
→ 真实示例或结果
→ 常见失败点
→ 适合谁、不适合谁
→ 下一步学习方向
```

### 质量要求

- 根据长文阅读场景重新组织，不机械拉长短内容。
- 核心步骤需要完整，不故意缺失。
- 外部事实附来源和时间。
- 图片紧跟对应步骤。
- 文末产品承接与正文自然相关。

### 发布包

- 标题候选 3 个。
- 摘要。
- 正文 Markdown 或 HTML。
- 封面图。
- 正文配图。
- 图片替代文本或说明。
- 来源清单。
- CTA 和风险提示。

## 2. X

### 目标

- 输出判断和洞察。
- 参与行业讨论。
- 快速验证选题。

### 适合形式

- 单条结论。
- 3 至 7 条短 Thread。
- 实验结果和前后对比。
- 产品经理视角下的取舍。
- 教程中的一个关键洞察。

### 要求

- 不把公众号机械压缩。
- 不把中文直接机器翻译成英文。
- 中文或英文版本分别按目标读者重写。
- 事实仍需保留来源，特别是热点和产品更新。

## 3. 公众号配图

### 视觉优先级

- 真实产品截图和操作结果：60%。
- HTML/SVG 信息图、流程图和表格：30%。
- AI 生成概念图：10%。

比例是初始建议，可随数据调整。

### 图片类型

- 封面图。
- 关键操作截图。
- 流程图。
- 前后对比图。
- 模型或方案对比表。
- 提示词卡片。
- 失败界面和排错说明。

### 自动处理

- 裁切和比例适配。
- 隐私信息打码。
- 关键区域标注。
- 统一圆角、边距和字体。
- 标题自动换行。
- 图片顺序和文件命名。

## 4. 一份母题的文件结构

```text
content-package/
├── brief.md
├── research-pack.md
├── evidence/
├── wechat/
│   ├── article.md
│   ├── cover.png
│   └── images/
├── x/
│   ├── single-posts.md
│   └── thread.md
├── sources.md
└── review-report.md
```

## 5. 发布前的动态核验

发布动作前必须确认最新规则，至少记录：

- 核验日期。
- 规则来源。
- 是否需要 AI 辅助标识。
- 是否涉及商业推广标识。
- 是否允许当前链接、私信或引导方式。
- 自动化上传是否被允许。

未经核验，不将平台规则写死在代码中。
